How to create your own tool

Every ProteomIQon tool is a small console project located in src/, containing three files with distinct responsibilities.

01
CLIArgumentParsing.fs

Declares command-line arguments using Argu.

02
Program.fs

Parses arguments, reads the parameter JSON and loops over input files.

03
Tool-specific implementation

Contains the actual processing logic.

Shared components

Parameter records and result row types shared between tools are located in src/ProteomIQon/ in the core project.

Scaffolding from the template

The repository ships a dotnet new template that creates this layout. Follow these steps to set up your new tool.

01
Install the template

Run the following command once from the repository root:

dotnet new install ./ConsoleTemplate/template
02
Create your project

Run dotnet new list to verify that pct (the prototypical ProteomIQon console project) is available.

Then create your project inside src/ and add it to the solution:

                                
                                    cd src
                                    dotnet new pct -n MyTool --force
                                    cd ..
                                    dotnet sln ProteomIQon.sln add src/MyTool/MyTool.fsproj
Information

Compare the new .fsproj with an existing tool such as src/PeptideDB/PeptideDB.fsproj. Use its target framework, package versions, PackAsTool and ToolCommandName properties as references.

Wiring the tool in

Four more places need to know about the tool:

01

A parameter record in src/ProteomIQon/DTO.fs with a toDomain conversion, plus a default JSON file in src/ProteomIQon/defaultParams/. The tools read parameters with Json.ReadAndDeserialize.

02

A RELEASE_NOTES.md in the project folder. The build reads the package version from it.

03

An entry in the projects list of build/ProjectInfo.fs, so Build and Pack include it.

04

A page in docs/tools/; see How to document your work.

Next step

Then open a pull request against dev.

How to document your work

01

The pages on this site are literate F# scripts under docs/, rendered with the fsdocs tool.

02

Prose lives in (** ... *) comment blocks as Markdown; code between the blocks is shown with syntax highlighting and tooltips.

Building the docs locally

01

From the repository root, restore the tools once and then run the docs target. It builds the core project in Release and renders the site into output/: 

dotnet tool restore
.\build.cmd builddocs
02

On Linux or macOS use ./build.sh builddocs. For editing with hot reload use the watch target. It serves the site on a local port and re-renders a page whenever you save it: 

.\build.cmd watchdocs

Adding a page for a tool

01

Copy an existing file from docs/tools/, for example PeptideDB.fsx, rename it after the tool folder in src/, and adjust the frontmatter at the top. The index value sets the position in the sidebar. The pages are ordered along the processing chain, so pick the slot where the new tool fits and shift the later ones if needed.

02

Each tool page has the same four parts: a short description of what the tool does and where it sits in the chain, an inputs and outputs section, the parameter table with the defaults from src/ProteomIQon/defaultParams/, and the script that writes a parameter file followed by the command line calls. Tools without a parameter file skip the table and the script.

03

Keep the parameter script runnable. It references the core assembly built by builddocs, so this proves it before you publish: 

dotnet fsi docs/tools/YourTool.fsx
